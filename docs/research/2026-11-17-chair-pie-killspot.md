# 椅子とパイの有限模型：外部条件の最小証明書とキル・スポット

作成日：2026-11-17。由来：会話「クソ玉を安価に巨大化させられる」「椅子とパイ」「キル・スポット」。

## 1. 既存研究との差分

`primitive-lean` の `linear_input/lean_check/OperatorReachability.inc` には、既存の操作列を新しい一文字にコンパイルしても、元の状態空間での到達可能性は増えない、という定理 `generated_extension_reachability` が既に存在する。

出典：https://github.com/Sumuji-zkdwn/primitive-lean/blob/main/linear_input/lean_check/OperatorReachability.inc

今回の追加はその定理の再発見ではない。**外部条件の有限集合**を動かし、収益到達のための最小条件集合と、その全経路を塞ぐ最小条件集合を抽出する。これを「椅子とパイ」の操作可能な模型とする。

## 2. 抽象定義

状態空間を `X`、初期状態を `x₀`、目標状態集合を `G`、内部操作の集合を `I`、使用可能になり得る外部イベントの有限集合を `E` とする。`A ⊆ E` のとき、内部操作と `A` に属する外部イベントを任意回使用して `G` に到達できるかどうかを

`f(A) = 1  ⇔  x₀ から G へ I ∪ A の有限操作列で到達可能`

と定義する。外部イベントの**可能性**を仮定する存在的到達性であって、実際の需要・購入・実現確率を表してはいない。`A ⊆ B` なら `f(A) ≤ f(B)` が成立する（使える操作を増やしても既存の証明列は失われない）。

**最小収益化条件**（最小許可証明書）を、`f(A)=1` かつ任意の真部分集合 `A'⊊A` について `f(A')=0` となる `A` とする。それらの集合族を `M` と書く。

**遮断集合** `K⊆E` を、`f(E\K)=0` となる外部条件の集合とする。`K` が包含順序で最小なら最小キル・スポット集合と呼ぶ（単一要素とは限らない）。

### 命題：最小証明書と遮断集合の双対性

有限 `E` について、任意の `K⊆E` に対し

`f(E\K)=0  ⇔  すべての A∈M について A∩K≠∅`

が成り立つ。

**証明**：`f(E\K)=1` なら有限性により `E\K` の内部に包含最小の成功集合 `A` が存在する。この `A` は `M` に属し、`A∩K=∅`。逆に `A∈M` で `A∩K=∅` なら `A⊆E\K` であり、単調性から `f(E\K)=1`。両方向の対偶を取ればよい。□

この命題は既存の**単調ブール関数・ハイパーグラフの横断集合**に属する初等的事実であり、一般数学上の新定理という主張ではない。「椅子とパイ」から具体的に計算可能な新しい研究対象を取り出した、という意味での新規追加である。

## 3. 有限の実装模型

状態は `(capability, unlocked, paid)`。`grow` は能力を閾値 `h` まで増やす。外部イベントは椅子へのアクセスや購入者の登場を `unlocked` に記録する。`sale` は能力 `h` 以上かつチャンネルごとの必要条件が揃っているときだけ `paid=True` にする。

初期状態は `(0, ∅, False)`、通常の計算は `h=3`。最短成功列では `grow` が3回必要になる。外部イベントはモデル上で「利用できる候補」であり、AIが強制できる操作という意味ではない。

| 模型 | 最小の収益化条件集合 | 最小の遮断集合 |
|---|---|---|
| 1チャンネル | `{chair,demand}` | `{chair}`, `{demand}` |
| 独立2チャンネル | `{chairA,demandA}`, `{chairB,demandB}` | `{chairA,chairB}`, `{chairA,demandB}`, `{chairB,demandA}`, `{demandA,demandB}` |
| 椅子2つ・購入者共有 | `{buyer,chairA}`, `{buyer,chairB}` | `{buyer}`, `{chairA,chairB}` |
| 内部で椅子を自作 | `{demand}` | `{demand}` |

### 注目すべき反例

- **椅子を2つ作っても脆弱性は除去できない**：共通の `buyer` が全経路に含まれるなら `{buyer}` は依然として単独のキル・スポット。
- **椅子の自作が可能なら必要な外部条件が減る**：`internal:make-chair` を新しい内部プリミティブとして追加した模型では、外部からの `chair` は不要になる。ただし外部 `demand` は依然として必要。これは現実に椅子を自作できたという実証ではない。
- **単なる能力増大では遮断集合を変えない**：閾値 `h=0,1,3,8,30` で1チャンネルの最短経路長はそれぞれ `3,4,6,11,33` だが、必要な外部条件は常に `{chair,buyer}` の2つ。能力の量と外部境界の構造は別の変数。

## 4. 検証結果

`python tools/chair_pie_killspot.py` を実行し、次を確認した。回帰テストは `python -m unittest discover -s tests -p test_chair_pie_killspot.py` で実行できる。

1. 各模型で外部条件の**全部分集合**に対して幅優先探索（BFS）で到達可能性を判定し、独立に書いたチャンネル条件式と全件照合。
2. すべての部分集合対における収益到達性の単調性を検査。
3. **全**候補遮断集合について、最小証明書の横断条件との同値を検査。
4. 最短経路を一手ずつ再実行して成功状態を再確認。
5. 外部条件が1つもない場合、内部拡張のみで収益化されないことを確認（今回の4模型）。
6. 境界例として、成功経路が一切ない模型と、外部条件ゼロで成功する模型の両方を検査。
7. 模型とは独立に、外部条件4個に対する**単調ブール関数168個すべて**について、双対性を網羅的に検査。

実行結果：**PASS**（標準Python 3.13、外部ライブラリ不要）。


### Lean 形式化（2026-11-17）

`lean/Research/ChairPieKillSpot.lean` を独立した Mathlib モジュールとして追加した。リポジトリのピン留めされた Lean `v4.30.0-rc2` において、次を定義・証明した。

- `Allowed`, `run`, `RevenuePossible`：内部操作と外部許可付き操作による有限語の存在的到達可能性。
- `allowed_mono`, `revenue_mono`：利用可能な外部条件を増やしても旧経路は失われない。
- `MinimalEnabler`, `minimal_enabler_exists_iff`：成功する有限条件集合には包含最小の証明書が存在する。
- `Blocks`, `blocks_iff_hits_minimal`, `revenue_blocks_iff`：外部条件を除去して失敗することと、すべての最小成功証明書を横断することの同値。
- `MinimalBlocker`, `minimal_blocker_exists_of_no_free_success`, `minimal_blocker_iff_minimal_hitting`：条件のない成功が不可能なら最小遮断集合が存在し、それは包含最小の横断集合に一致する。
- `SharedBuyer`, `two_chairs_without_buyer`, `shared_buyer_killspot`：共通購入者が二つの椅子を同時に遮断し得る具体例。

**検証証拠**：PR #145 ヘッド `ccb446c57d792b6f2ea9aa87ad416a92db59a90b` で、GitHub Actions [run 43980669322](https://github.com/Sumuji-zkdwn/primitive-lean/actions/runs/43980669322) の `lean-kernel-check` と `finite-check` が双方 success。Lean は `lake env lean --trust=0 Research/ChairPieKillSpot.lean` で直接コンパイルし、`#print axioms` の出力に `sorryAx` が含まれないことを監査した。

**厳密な境界**：Lean は一般の決定的有限語操作系と抽象的な共有購入者模型について証明した。Python の `Economy` の `grow` / `internal_unlocks` / `sale` の全実装と Lean の操作系の同値性、4具体模型の最小集合の全列挙、168個の単調ブール関数の列挙それ自体は Lean に移植していない。それらは独立したPython全探索・回帰テストによる検証であり、数学的な一般定理のLean証明とは区別する。

## 6. 次の研究課題

外部イベントの全くない閉鎖系と、内部で新たな椅子を生成できる状態拡張とを、**状態射影と操作の模倣関係**で区別する。`OperatorReachability.inc` の既存定理は同じ旧状態空間上の操作列コンパイルを扱うが、状態空間そのものが拡張されたとき、射影後の到達可能性が保存されるための条件を別途定式化できる。この差分をLean形式化すると、CCCの自己拡張と「椅子とパイ」の境界をつなぐ補題になる。
