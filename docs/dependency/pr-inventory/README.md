# 未統合 PR の棚卸し：カーネル水準の測定（2026-11-07）

`main` = `67fdf6b` に対して、未統合 PR 58 件を測定した結果です。判定案と ERG のラウンド記録は ERG-Aout の `logs/2026-11-07-primitive-lean-pr-inventory/` にあります。ここでは測定方法と数値を記録します。

## 読み方の前提

- 数値は「Lean が受理した項に現れる定数」に基づきます。依存の数学的な必要性や、内容の新規性を判定したものではありません。
- `main` を参照しないことは、`main` から導出できないことの証明ではありません。
- 判定案は候補です。採否は人が決めます。

## 方法

1. **構造（git のみ）**：`tools/deps/pr_inventory.py`
   - PR ごとに、`main` との分岐点からヘッドまでに追加・変更された Lean ファイルを、パスとブロブ SHA で記録します。
   - 積み重なった PR では、親 PR のヘッドにない分を、その PR 固有の内容とします。
   - すでに `main` に同一バイトで入っているファイルは除外します。
2. **カーネル**：`tools/deps/pr_kernel.py`
   - 他の PR に含まれない先端のヘッドごとに、そのヘッド自身の `tools/verify.py --proof-only` を実行します。
   - 組み立てを `.olean` にし、未登録のプローブと独立した `lean/*.lean` も同じ環境でコンパイルして、依存を抽出します。
   - 作業ディレクトリを `LEAN_PATH` の先頭に置く呼出しでは、パスを固定のシェル文字列に埋め込まず、環境変数 `PR_KERNEL_WORK` と位置引数で渡します（空白入りパスの回帰テストは `tests/test_pr_kernel_paths.py`、記録は [2026-11-07 の検証記録](../../verification/2026-11-07-pr-kernel-path-arguments.md)）。上の表の測定はこの変更前の実行です。
   - プローブを PR 自身の CI が単独ファイルとしてコンパイルしている場合（#50〜#54）は、同じ方法で単独に測定しました。
3. **集計**：`tools/deps/pr_compare.py`
   - `main` にない宣言のうち、PR 固有ファイルに属するものを、その PR の新しい内容とします。
   - 同じ内容を含む測定が複数あるときは、その PR のファイルに最も多くの宣言が帰属する測定を使います。
4. **CI**：GitHub Actions の実行履歴（1200 件）を PR ヘッドの SHA で突き合わせました。
