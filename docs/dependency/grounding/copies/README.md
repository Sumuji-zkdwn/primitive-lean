# 初期の定義の「作り直された写し」の検出

「新しい対象」（初期層に触れずに定義されたプロジェクトの定義）が、名前を変えただけの初期の定義ではないかを調べた。

## 方法

1. **第 1 段（定義の展開による同一性）**：候補と初期の定義 46 個の全組について、型が定義的に等しいかを `isDefEq` で調べ、等しい組は定数そのものの `isDefEq` を調べる（`tools/deps/CopyCheck.lean`）。宇宙パラメータは新しいメタ変数で単一化する。
2. **第 2 段（代数による同一性）**：型が等しく第 1 段で同一とされなかった組について、`funext` → 両方を展開 → `ring` で `C = I` の証明を試みる（`tools/deps/copy_ring_stage.py`）。
3. **対照**（`control/`）：`f`・`E`・`input` を別名で書き写したものは第 1 段で、項の順序を入れ替えた `f` は第 2 段で同一と判定された。値の違う関数は同一とされなかった。

第 1 段で同一とされたのは 1 組だけで、`DarkBrightObservation.Summary` と Elastica 内部の型の別名 `Parameters` である。どちらも実数の組を表す型の名前で、数学的な対象の写しではない。第 2 段の失敗は、ログを確認したところ、すべて目標の値が実際に異なる（`unsolved goals`、`ring_nf made no progress`）ものだった。

副産物として、初期層の内部で `LinearInputCalculus.potential` と `LinearInputDesign.f` が定義として同一であることが分かった（対照実験の出力）。

## この検査が見ないもの

- 型の形が違う写し：引数の順序が違う、パラメータを固定した特殊化、組にまとめた引数など。
- `private` な定義との第 2 段の比較（別ファイルから名前を参照できないため）。
- 展開と `ring` で示せない同一性（三角関数の恒等式、場合分け、極限など）。

したがって「新しい対象」の数は、少なくとも型の形が同じ写しを含まないことまでは確かめたが、意味的に初期の対象と同じものが残っている可能性は否定していない。
