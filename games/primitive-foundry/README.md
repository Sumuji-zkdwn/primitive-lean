従来のパズル・ROGUE465とは独立した工場自動化ゲームです。Factorioの「採掘→搬送→加工→研究→拡張」という仕組みを参考にした新規コードと独自のCanvas描画で、Factorioのソース・イラスト・音楽はコピーしていません。

## Androidでの操作（ブラウザ版）

Android Chromeの縦画面（約412×915）と横画面（約914×411）に合わせ、画面下に**工場・建設・詳細・研究・文書**の5タブを設置しています。画面下の安全領域（ジェスチャーナビゲーション領域）も避けます。

- **工場**：マップを広く表示。タップで欠損ベルトを補修したり、機械を選択したりできます。指1本でドラッグして移動、指2本でピンチ拡大・縮小します。
- **建設**：縦画面では建設パレットが下に、横画面では右側に開きます。ベルトをなぞると敷設し、方向を変えて配置できます。2本指操作では建設しません。
- **詳細**：最後にタップした設備の処理状況や詰まりを確認できます。
- **研究**：465定理・629本の直接証明参照を検索・研究。グラフのドラッグ、ピンチ拡大・縮小、ノードのタップに対応します。横画面では検索とグラフを左右に並べます。
- **文書**：回収した設計書を確認します。

通常URLに `?view=research` や `?view=build` を付ければ該当画面から開けます。元の単一HTML形式と自動保存を維持しています。これはAndroid向けに調整した**ブラウザゲーム**であり、Android APK/ネイティブアプリではありません。

## 遊び方

開始時は完成直前の工場で、**歯車ラインと導線ラインのベルトが各1マスずつ切断**されています。黄色い2つの欠損セルをタップして補修すると、採掘→精錬→歯車・導線製造→制御回路組立→研究の自動生産が始まります。建設パレットから自分でベルトを敷設して直すこともできます。「稼働ラインを再配置」で完成版を読み込み、自由に改造することもできます。

物流／製造／補助の建設パレットを選択後、マップ上をタップすると装置を置けます。ベルトは指でなぞって連続配置、曲がり角の向きも自動で接続。「調べる」ではタップで機械を調査、ドラッグで地図を移動。右上のボタンで再生・一時停止・速度を切り替えられます。

研究所が生産した制御回路を消費するごとに研究ポイントが1増えます。**初期465定理の研究画面**では、実際の証明項中に現れた直接の定理参照を前提に、研究ポイントを使って定理を順に解明できます。その到達点を使い、別枠の工場改良を解放します。累積3、10、25ポイントで謎の設計書が見つかり、10ポイントで東部の鉱脈地域が開きます。累積30研究ポイントを生産すると最初の目標達成。その後も操業できます。

## 主要設備とレシピ

- 鉱脈上の採掘機：鉄鉱石または銅鉱石を取り出す。
- 石炭鉱脈上の発電機：鉱脈を消費して電力を供給する。
- 鉄・銅の精錬炉：鉱石1個を板材1枚に変換する。
- プレス機：鉄板2 → 歯車1。
- 巻線機：銅板1 → 導線2。
- 組立機：歯車1 + 導線2 → 制御回路1。
- 研究所：制御回路1 → 研究ポイント1。
- ベルト：1タイル1部品を前方へ運ぶ。行き先が満杯なら止まる。
- 研究後の分配器：受け取った部品を前方／右方へ交互に送る。

これらのレシピや技術効果はゲーム設計であり、Leanの連続数学の帰結ではありません。

## 初期465定理すべての直接証明参照DAG

研究画面の中心となる tech.json は、**Elastica 214件 + LinearInput 251件 = 465定理**を全部登録した有向非巡回グラフです。従来の10ファイル単位の研究ノードは本体から分離しました。

出典は次の既存資料です。

- evidence/local/2026-10-30-f0/joint.json : 初期465定理の検証済み宣言目録
- games/rogue465/theorems.json : 初期465の宣言名・出典パス・行番号
- docs/dependency/data/deps.json : Leanが受理した証明項・命題型・定義本体に現れる定数参照のスナップショット

定理から他の初期定理への**直接の証明項参照は629本**。これらをそれぞれ研究の前提とします。定理同士の参照がない根は146件で、最長依存深さは12段です。元の証明項にはこのほか、定義などへの直接参照783本、private/補助定理への参照9本があり、tech.json内で別枠の参照として保持します。

これは「定理の証明項に別の定理の定数が現れる」という**証明項上の直接参照関係**であり、数学的な必要十分依存、最短証明、別の証明で導出できないことは意味しません。カーネル由来の参照は既存の履歴スナップショットに基づき、現在のmainでLeanからゼロからの再抽出をしたとは主張しません。

### 工場の研究と接続

- 465ノードの全体図と、特定の定理の前提・後続を辿る拡大図を表示できます。
- 定理名を直接表面に出さず、日本語の短い見出しと番号で検索・閲覧します。元のLean完全名・ファイル・行番号は「出典」の詳細で確認できます。
- 定理を研究するには、それを直接参照する親定理の研究がすべて完了し、必要な研究ポイントを払う必要があります。研究済みの状態は保存されます。
- **工場への機械的な効果は別の upgrades.json の設計プロジェクト**に分離しています。10プロジェクト中6件は、実際の465定理のうち対応する重要な定理に達しなければ解禁されません。前提となる定理を開くためには、629本のDAG辺を辿ります。工場能力値や研究費用はゲーム設計であってLeanの数学的命題から導いたものではありません。

再現可能な全件監査:

    python3 -B games/primitive-foundry/check_dag.py

これにより465件の宣言名・パス・行番号、629本の直接参照、定義・補助定理への残余参照、巡回の不存在、12段の深さと元データのハッシュを一件ずつ検査します。

Core.lean は、ベルト移動・採掘・精錬・組立に関する有限の保存則を形式化します。ブラウザの全JavaScriptの正しさをLeanで証明したという主張ではありません。
