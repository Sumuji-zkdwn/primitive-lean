# 追加列による解釈更新：有限検算

2026年11月21日の二段階の研究を再現するPythonスクリプトと、確認済みの計算結果です。実用暗号の実装ではありません。

定義・仮定・手証明・Leanで確認した範囲・有限検算を分けた入口は、[研究一覧](../../docs/research/2026-11-21-retroactive-translation.md)を参照してください。本文は[第1段階](../../docs/research/retroactive-translation-stage1.md)と[第2段階](../../docs/research/retroactive-translation-stage2.md)、実行記録は[検証記録](../../docs/verification/2026-11-21-retroactive-translation.md)にあります。

## 実行

Python 3.10以降、標準ライブラリのみ。リポジトリのルートで実行します。

```bash
python3 tools/check_retroactive_translation.py
```

4本の検証器を一時ディレクトリで実行し、生成した4個のJSONを同梱の結果と比較します。JSONの空白とオブジェクトのキー順だけを正規化し、全フィールドを比較します。成功時は `passed: true` のJSONを出力して終了コード0を返します。結果の欠落、改変、再計算との不一致、重複キー、不正なJSON、検証器の異常終了は失敗にします。同梱の結果を検査中に上書きしません。

Leanの汎用補題を含む統合入口は次です。

```bash
python3 tools/verify.py --retroactive-translation-only
```

assertを無効にする `-O` / `PYTHONOPTIMIZE` は、検査入口と各検証器が拒否します。個々の研究スクリプトを直接実行すると、対応する同梱JSONを再生成します。結果を変更する場合は、研究上の変更を確認したうえでスクリプトとJSONを一緒にレビューしてください。

## 読み取り上の境界

- 更新で多数の出力位置が変わること、候補数、解読費用を区別します。置換の合成や、全候補を保持する観測者が安価に追随できる反例を含みます。
- 旧要約からの因子化に関する有限検算と、一般命題の証明を区別します。結果JSON内の `lean_verification: not performed` は、元のPython実験がLeanを呼ばないことを記録したものです。今回追加するLean補題の検証状況は、研究一覧と検証記録で別に扱います。
- パリティの最適正答率は、各実現枝での最大照会数、独立な一様列選択、独立な公平ビットを仮定したoracle模型の結果です。期待照会数への置換が失敗する反例も確認します。
- `N=1024, M=256` の大規模表は公式からの予測値です。大規模全列挙、CPU時間、逐次実行時間の実測値ではありません。
- 反復二乗の小さな法は公開された容易に因数分解できる例です。演算数は特定の実装についての値で、一般攻撃者の下界ではありません。攻撃者の再利用可能な前処理と、正規側の事前費用も数えます。

このディレクトリの成功だけでは、期限までの暗号安全性や一般的な時間下界は確立しません。
